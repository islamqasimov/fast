========================================================
OSINT IOC COLLECTOR - İSTİFADƏ TƏLİMATI (USAGE.txt)
========================================================


1) İLK DƏFƏ QURAŞDIRMA (yalnız bir dəfə)
--------------------------------------------------------

    cd osint-ioc-collector
    pip install -r requirements.txt

Kali Linux-da paket ziddiyyəti xəbərdarlıqları (qırmızı mətn)
çıxsa da, sonda "Successfully installed ..." görürsənsə
hər şey qaydasındadır, davam et.


2) BAZANI YARATMAQ (--init-db) — LAZIMDIRMI?
--------------------------------------------------------

QISA CAVAB: XEYR, HƏR DƏFƏ LAZIM DEYİL.

    python3 cli.py --init-db

Bu əmr yalnız BİR DƏFƏ, ilk quraşdırmada işə salınmalıdır.
Səbəb:
  - Bu əmr "CREATE TABLE IF NOT EXISTS" istifadə edir,
    yəni fayl artıq varsa, təkrar işə salsan belə heç nəyi
    pozmur, sadəcə lazımsız bir addımdır.
  - Üstəlik, --fetch əmri özü daxilində avtomatik olaraq
    bazanı yoxlayıb lazım olsa yaradır. Yəni --init-db
    işlətmədən birbaşa --fetch ilə başlaya bilərsən.

NƏ VAXT --init-db LAZIM OLA BİLƏR:
  - Bazanı sıfırlamaq istəsən (aşağıda "Bazanı Sıfırlama"
    bölümünə bax)
  - Yeni bir mühitdə (təzə server, təzə klon) ilk dəfə
    işə salarkən (ehtiyat üçün, məcburi deyil)


3) GÜNDƏLİK İSTİFADƏ AXINI (ƏSAS İŞ ADDIMLARI)
--------------------------------------------------------

Addım 1 - Feed-lərdən yığ (fetch + normalize + dedup + score,
hamısı avtomatik bir əmrdə):

    python3 cli.py --fetch

Addım 2 - Nəticəyə bax:

    python3 cli.py --count          -> cəmi neçə IOC var
    python3 cli.py --show           -> cədvəl şəklində göstər
    python3 cli.py --show | head -30   -> yalnız ilk 30 sətir

Addım 3 - Export et (CSV/JSON faylı yaratmaq üçün):

    python3 cli.py --export csv     -> yalnız CSV
    python3 cli.py --export json    -> yalnız JSON
    python3 cli.py --export both    -> hər ikisi

Nəticə fayllar bu qovluqda yaranır:
    sample_output/ioc_export.csv
    sample_output/ioc_export.json


4) BÜTÜN CLI ƏMRLƏRİNİN SİYAHISI
--------------------------------------------------------

    --init-db          Bazanı yarat (adətən lazım deyil, bax bölüm 2)
    --fetch             4 feed-dən yığ, normallaşdır, bazaya yaz
    --count             Bazadakı toplam IOC sayını göstər
    --show              Bütün IOC-ları cədvəl şəklində göstər
    --export csv        CSV export et
    --export json       JSON export et
    --export both       Həm CSV, həm JSON export et

Bir neçəsini birlikdə də yaza bilərsən:

    python3 cli.py --fetch --show --export both


5) NƏ QƏDƏR TEZ-TEZ --fetch İŞLƏTMƏLİYƏM?
--------------------------------------------------------

Feed-lər (Feodo, URLhaus, MalwareBazaar, Spamhaus) adətən
gündə bir neçə dəfə yenilənir. Gündə 1 dəfə --fetch işə
salmaq kifayətdir. Hər --fetch:
  - Yeni IOC-ları əlavə edir
  - Artıq mövcud olanların "last_seen" tarixini və
    confidence_score-unu yeniləyir (dedup avtomatik işləyir)
  - Heç bir dublikat sətir yaratmır

Qeyd: Gələcəkdə scheduler.py ilə bu proses avtomatlaşdırılacaq
(gündəlik özbaşına işə düşəcək), hazırda əl ilə çağırılır.


6) BAZANI SIFIRLAMA (TƏMİZ BAŞLANĞIC)
--------------------------------------------------------

Əgər bazanı tamam təmizləyib yenidən başlamaq istəsən:

    rm ioc_database.db
    python3 cli.py --init-db
    python3 cli.py --fetch


7) TESTLƏRİ İŞƏ SALMA (İSTƏYƏ BAĞLI)
--------------------------------------------------------

    python3 -m pytest tests/ -v

Bütün testlər mock (saxta) data ilə yazılıb, ona görə
internet olmasa belə keçəcək. Yalnız fetchers testlərindən
bəziləri (test_fetch_feodo və s.) real internetlə əlaqəli
işləyir və şəbəkə olmadıqda belə crash etmədən boş nəticə
qaytarır (bu, gözlənilən davranışdır).


8) TEZ-TEZ RAST GƏLİNƏN SUALLAR
--------------------------------------------------------

S: confidence_score niyə çoxu 25-dir?
C: 25 bal o deməkdir ki, həmin IOC yalnız 1 feed-də görünüb.
   50/75/100 yalnız eyni IOC (eyni string dəyəri) bir neçə
   fərqli feed-də görünəndə yaranır. Feed-lər fərqli format
   (tək IP / CIDR blok / URL / hash) verdiyi üçün bu nadir
   hadisədir - bu, bug deyil, gözlənilən davranışdır.

S: --fetch zamanı hansısa feed "0 IOC" göstərir, niyə?
C: Loglara bax - əgər "HTTP 403", "Timeout" və ya
   "Bağlantı xətası" görürsənsə, demək ki, o feed müvəqqəti
   əlçatan deyil (server tərəfindən bloklanıb və ya şəbəkə
   problemi var). Proqram çökmür, sadəcə o feed-i keçir və
   digərləri ilə davam edir. Bir az sonra yenidən sına.

S: pip install zamanı qırmızı "dependency conflict" xəbərdarlıqları
   çıxır, problem varmı?
C: Xeyr. Bu, sistemdə əvvəldən olan başqa alətlərin (Kali
   Linux-da pentesting alətləri kimi) versiya tələbləri ilə
   bağlıdır, bizim layihəyə aid deyil. "Successfully installed"
   sətri görünürsə, hər şey qaydasındadır.


9) VEB İNTERFEYS (DASHBOARD)
--------------------------------------------------------

CLI-dən əlavə, brauzerdə istifadə üçün dashboard da var.

Başlatmaq üçün:

    python3 app.py

Sonra brauzerdə aç:

    http://localhost:5000

Dashboard-da bunları edə bilərsən:
  - "Fetch feeds" düyməsi ilə 4 feed-i yığmaq (CLI-dəki --fetch
    ilə eynidir)
  - Cəmi IOC sayı, tip üzrə bölgü, feed əhatəsi statistikasını
    görmək
  - IOC-ları tipə (ip/url/hash/domain), feed-ə görə filtrləmək
    və ya axtarış qutusu ilə axtarmaq
  - "CSV" / "JSON" düymələri ilə export edib birbaşa yükləmək

Qeyd: Dashboard və CLI eyni verilənlər bazasını (ioc_database.db)
və eyni core/ məntiqini istifadə edir - hər hansı biri ilə
etdiyin dəyişiklik digərində də görünür.

Dayandırmaq üçün terminalda CTRL+C.
