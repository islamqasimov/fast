## What landed

- `compose/docker-compose.yml` - Wazuh single-node stack (manager + indexer + dashboard) on a user-defined `fast_net` bridge, plus `agent-linux` test container and the `talon` service placeholder. All images declare a SHA256 digest placeholder.
- `etc/fast.env.example` - the only env file in git. Real `.env` is gitignored.
- `etc/fast.env` - generated copy (gitignored).
- `installer/install.sh` - bash installer with `--mode interactive|unattended`, `--no-cron`, `--expose-dashboard`, `--yes` flags.
- `installer/lib/secrets.sh` - policy-validating secret generation.
- `installer/lib/cron.sh` - idempotent `/etc/cron.d/talon` install.
- `installer/lib/firewall.sh` - iptables rules so only the talon container has outbound access.
- `bin/fast` - thin CLI dispatcher.
- `README.md` - human intro.
- `CONTEXT.md` - AI rules.
- `setup-vm.sh` - one-shot script for the VM.
- `docs/image-digests.md` - digest registry.

## Decisions worth flagging

- **Talon image is built locally** (`build: ../talon`). The cron-driven daily run is a host-level invocation, not a container scheduler. If Nihat's `talon` package starts in week 2, this compose entry will start succeeding.
- **Secrets are referenced by file path from `etc/fast.env`**, never inline. This is the "no plaintext secrets" hard rule.
- **Talon is the only container with outbound access**, enforced by `installer/lib/firewall.sh`. The rule is added on every install, idempotent.
- **Dashboard binds to `127.0.0.1:443` by default**. The `--expose-dashboard` flag flips this to `0.0.0.0:443` (via a separate compose override file, TBD).
